## Browser M5: JavaScript runs while a page loads, with a DOM (2026-11-14)
**Working in QEMU: `python3 tools/ui_browser.py` = ALL PASS (85 of 85)**, 172 host tests pass. New checks: `/js` page (a script file, inline DOM building, a timer, a throwing script); the old `/` page now expects its script's red. Not run since these changes: `ui_browser.py norng` / `virtiorng`, `make qemu-test` and the other suites (the disk layout, storage server, program manager and `Command` changed).

**What it took to get there (all fixed):** (1) `MAX_PACKAGE` 4 MiB refused the 6.9 MB package: now 12 MiB, but **an unsigned package is capped at 4 MiB by `metal_map::check`** (`MAX_PACKAGE_UNSIGNED`, `TrustError::UnsignedTooLarge`), loader `MAX_FILE` 8 MiB; (2) install copies the package to `/data`: the data partition is now **the rest of the disk** (the storage server asks the block driver, `BLK_INFO`; `tools/mkdisk.py` takes `DATA_MIB`, default 5.5 so the QEMU suites' cleaner test still overruns it; sparse files; `make run-window` uses 1024, `ui_browser.py` 256; a 32 GiB disk file costs 6.6 MiB on the host, untested in a guest); (3) the program manager ran out of heap starting a 6.9 MB program: `launch` now cuts the ELF out of the package buffer in place and `Command::image` shares it (`Arc`) instead of cloning; **the kernel caps any heap at 4096 pages (16 MiB, `MAX_HEAP`)**, so the manager stays at 4096; (4) **the browser heap was 12 MiB full of fonts**: `fontdue` expands each embedded 190 KB font into ~2.4 MiB of outlines, and all 5 were parsed at startup; `FontSet` now parses each on first use (a page using all five is back to ~12 MiB: the 16 MiB heap is tight, the heap after the engine starts is ~9.9 MiB for a normal page; `heap::grown_bytes()` shows the total taken); (5) the test waits for `install: ok` instead of a fixed 6 s.
* **Engine: Kataan 0.0.10** (pure Rust, MIT, `alloc` + `regex` features; deps `puremp`, `timezone-data`; PROVENANCE.md). Chosen after a spike: Boa ~10 MB and not `no_std`, MicroQuickJS is C and ES5-ish. Browser PIE 2.87 -> 6.88 MB, system image 3.15 -> 4.70 MB (zstd), partition now 6 MiB.
* **Disk layout 4:** system partition 4 -> 6 MiB (sectors 1024..13311), data at 13312 (11264 sectors, unchanged), disk 12 MiB. `tools/mkdisk.py`, `user/src/storage.rs`, `tools/checkdisk.py`, `layout=4`: an old `disk.img` is not kept (saved colours, settings, installed programs lost once).
* **How it works.** `src/dom.rs` got a mutation API (`create_element/text`, `insert_before`, `append_child`, `detach`, `set_attr`, `set_text_content`, `set_inner_html`, `serialize`, `clone_subtree`, `get_by_id`, `query`/selector lists through `css::parse_selector` + `css::matches`); nodes are never freed. `src/js.rs`: `Js` (engine + `Rc<RefCell<Dom>>` + console), host functions `__n.*` taking node ids (names in `NATIVES`), `script_sources(&Dom)`, `run_scripts`, `click(id)`, `watchdog()/arm()/set_watchdog()`. `src/prelude.js` (include_str!) builds the web API in JS over those: `document` (getElementById, querySelector(All), createElement, createTextNode, body/head/title...), `Node/Element/Text`, textContent / innerHTML / outerHTML / attributes / `classList` / `style` (Proxy over the `style` attribute) / `dataset`, appendChild / insertBefore / removeChild / remove / append / prepend / before / after, `matches` / `closest`, events (capture-less: target, bubbling to document and window, preventDefault, stopPropagation, `CustomEvent`), `DOMContentLoaded` / `load`, timers on a **virtual clock**, a stubbed window (navigator, location, localStorage in memory, matchMedia ...), `console.*`. Accessors are in JS because Kataan has no native accessor API.
* **Page load (`programs/browser/main.rs`):** `fetch_page` -> `run_page_scripts`: collects classic scripts (not modules / JSON), fetches up to 12 files (1 MiB each, `Req::sub("*/*")`), runs them on a **script thread with a 1 MiB stack** (the engine's recursion limit comes from the stack it is told about; the main stack is 64 KiB); the fetch thread is the **watchdog** (4 s, then trips the engine's `Interrupt`; a tripped page runs nothing more). After the scripts: `DOMContentLoaded`, `load`, timers due within 5 s of virtual time (max 2000 callbacks). The page is then **serialized back to markup and parsed again** (`Loaded::scripted`), so the layout / painter code is unchanged; stylesheets are those of the scripted page. Status line says "N scripts, M failed (first error)". `html.rs` now keeps `<script>` text as a text token (the text-only builder still hides scripts).
* **Not there (next):** scripts that react after the load (clicks call `Js::click` but the realm is dropped after load; no live realm per page, so no event handlers, no timers later than 5 s, no `requestAnimationFrame` loop), `fetch` / `XMLHttpRequest`, `document.write`, forms values (`input.value` reads the attribute only), computed style / layout queries (`getBoundingClientRect` is zeros), `location` is empty, cookies, `<script type=module>`, `async/defer` ordering, `javascript:` URLs, `innerHTML` for `<script>` insertion running. A live realm needs the `Js` to stay on its thread (it is `!Send`): a per-tab script thread with a message queue is the plan.
* **Risks to check on first boot:** (1) the manifest now has `threads = 6` (fetch + script thread per tab + pictures) and the browser `heap_pages = 4096`; a kernel-made 1 MiB stack may count against the program's page budget, the program manager's heap (3600 pages, budget 12000) was sized before the PIE grew by 4 MB; (2) the engine is ~650 KiB at idle and ~10 MiB for a 20 000-key object: only the 4 s watchdog bounds time, **memory is not capped** (the `Limits` of `Interp::new_with_limits` could be used: `max_string_len`, `max_array_len`); (3) `make browser-test` sets `RUST_MIN_STACK=32 MiB` because the engine is tested in a debug build (frames are large) and the test realm is told it has 24 MiB.
* **Stack rule:** `Js::new(stack)` / `eval` call `kataan::stack::set_thread_stack_size`; a `Js` must stay on the thread it was made on; host tests take turns on a mutex (the limit is one process-wide address without `std`).

## Kernel layering (framekernel style, 2026-11-13)
